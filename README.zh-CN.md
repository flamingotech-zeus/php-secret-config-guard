# PHP 密钥配置安全存放

[English](README.md) | [简体中文](README.zh-CN.md)

> 在 PHP 项目里安全存放密钥配置，并绕开一个会静默截断整个文件的陷阱。

## 这是什么

> **脱敏说明。** 本 README 已经写成通用版本。技能文件本身可能仍带有内部域名、主机名或本机绝对路径。发布前请先跑一遍扫描（见 `opensource-preflight-audit`），把命中的内容替换掉。

这里有两半，第二半才是这个技能存在的理由。

第一半比较常规：密钥别放在网站根目录里、别进版本控制、别放在任何请求够得着的地方。第二半是一个具体的陷阱 —— 注释里的 PHP 结束标记会把脚本截断。它后面的所有内容会被当成纯文本发给客户端，也就是说你的凭据、你的配置、文件剩下的部分，全部打印到浏览器上。

而这个症状看起来完全不像语法问题。所有 PHP 接口同时开始返回源码片段，人的第一反应通常是去查部署或者缓存。

## 为什么开源

我们撞过一次。排查花的时间比修长得多 —— 这类陷阱大多是这个比例，也正是它值得写下来的原因。

它是一条可以带走的 PHP 运维经验，里面没有属于我们的东西。任何在面板环境下跑 PHP 的人，离它都只差一次手滑。

## 能做什么

- **凭据该放哪。** 一套让密钥待在网站根目录外、版本控制外的配置布局，包含路径的处理方式也写明了。
- **截断陷阱讲清楚。** 为什么注释里的 PHP 结束标记会终止脚本、客户端因此收到什么、以及怎么快速认出它。
- **两种修法。** 要么干脆不写结束标记，要么改文件结构让注释无法终止它。
- **排查线索。** 那个特征症状 —— 所有接口同时返回源码片段 —— 以及为什么它指向这里，而不是部署。

## 环境要求

## 安装

```bash
git clone https://github.com/<你的用户名>/php-secret-config-guard.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\php-secret-config-guard\` |
| macOS / Linux | `~/.workbuddy/skills/php-secret-config-guard/` |

没有构建步骤，重启对话即生效。

## 注意与边界

1. **这个陷阱是"失效开放"，不是"失效关闭"。** 文件不会报错，它把自己的内容发出去。默认那个文件里的所有内容都已经暴露过。
2. **改布局，不只是改那个文件。** 挪一个结束标记解决的是一个实例；把密钥移出网站根目录消掉的是这一类。
3. **检查已经被发出去的内容。** 如果这事在生产环境发生过，把那个文件里的凭据全部轮换。删掉那一行，不能让已经发出去的东西收回来。
